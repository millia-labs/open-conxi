# Stress test, 23 Sep 2026 (v0.2.0)

Method. The 0.2.0 package was packed and installed as project skills into a fresh folder per case, with the mock 120-key Kuala Lumpur hotel (setup ran in an empty folder). Each case was a fresh Claude Code session on Sonnet, typed the way a rushed GM types: lowercase, hedged figures, missing inputs, instructions to claim things that had not happened. A fake Beeper Desktop recorded every draft and send; no real chat was touched. 29 cases in round 1 across all 13 skills and the CLI, then every failed case re-run on the fixed build with its original prompts.

## Round 1: what broke

| Skill | Failure |
|---|---|
| hotel-routine | Worked out 82 stayovers from rooms sold when the paste listed 10, and told managers the hotel was oversold by one room |
| work-orders | Said it saved when it had stopped to ask a question; team message said vendors were "dispatched"; a repeat report erased an open order's SLA breach; invented an open time of midnight |
| staff-roster | Applied an unpaid rest-day rule literally and put five people over the 45 hour weekly cap; put pay terms in the all-staff message |
| owner-report | Filled a missing utilities bill with the budget figure and said GOP beat budget "either way"; keyed the month on its last day, overwriting that day's flash |
| review-replies | Claimed an aircon service for a room the trace did not cover; wrote a public refund mention; guessed a Chinese name and a male title |
| ota-reconciliation | Kept stale share values and overwrote all-cost commission with commission-only figures |
| rate-check | Classified dates inconsistently and claimed a last-year comparison from rows that have no last-year field |
| morning-flash | Saved "around 33k" and "108 I think" as actuals |
| hotel-setup | Mapped one staff group to all-staff only, so housekeeping and maintenance messages had nowhere to go |
| CLI | `--text --send` sent the word "--send" to a chat; a broken data file showed as an empty hotel |

## Round 2: same prompts, fixed build

All ten failures above held up on re-run. New, smaller findings, fixed and re-run in round 3: a review linked to a work order on a room nobody named, the turnover board not printed after a straight-away send, "dispatched" in one work-orders team message, and a Malay honorific the reviewer did not use.

## What code now enforces, whatever the model does
- `team send` refuses messages over 900 characters or with long dashes, never takes a flag as the message, stops when a role has no chat in the profile, and never overwrites a half-typed draft.
- `tidy` clears long dashes from the hotel's files after every save.
- The dashboard server keeps the last good data and shows a plain warning when hotel-data.json breaks.

## Still open
Long dashes in Claude's own chat replies (not in files or staff messages) persist in about two thirds of runs despite the rule. They are a model habit; the files and messages that leave the conversation are clean.
